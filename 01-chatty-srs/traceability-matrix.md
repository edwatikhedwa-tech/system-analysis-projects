# Матрица трассировки — Chatty 2.0, блок видеоконтекста

Связь между потребностью пользователя, вариантом использования, функциональным требованием, атрибутом качества и бизнес-правилом. Матрица отвечает на два вопроса: **не потеряно ли требование по пути от сценария к реализации** и **что именно сломается, если требование не выполнить**.

Охватывает мою часть спецификации. Требования базовой версии Chatty 1.0 сюда не входят.

## 2. Обратная трассировка: требование → чем обосновано

| Требование | Откуда взялось | Что произойдёт, если не выполнить |
| :--- | :--- | :--- |
| `.ПросмотретьВидеоролик` | ВИ-11, базовый сценарий | Функциональность отсутствует |
| `.Закрыть` | ВИ-11, завершение сценария | Пользователь не может выйти из просмотра штатным способом |
| `.Ошибка` | ВИ-11 3а1, 3а2 + БП-7 | При недоступности библиотеки пользователь остаётся с пустым экраном вместо слова и озвучки |
| `.Кэширование` | УИ-4 + БП-5 | Либо рваное воспроизведение, либо нарушение лицензии на контент |
| `.Субтитры` | ВИ-11 3а3 + БП-6 | Пользователь не понимает, почему субтитров нет, и считает это дефектом |
| Про-4 | ВИ-11 шаг 2 | Нет измеримого критерия «видео запускается быстро» — приёмка превращается в спор |
| УИ-4 | ВИ-11 шаги 2–3 | Повторный просмотр каждый раз начинается с задержки |
| Над-1 | ВИ-11 3а2, БП-7 | Бесконечные попытки загрузки вместо деградации к текстовой карточке |
| Над-2 | Зав-3 | Разовый сбой библиотеки выключает функциональность до перезагрузки страницы |
| ДК-1 | Зав-3 | Нет договорённости об уровне доступности внешнего контента |
| ДК-2 | ВИ-11 3а1, 3а3 | Молчаливый отказ: пользователь не понимает состояние системы |

## 3. Покрытие бизнес-правил

| Бизнес-правило | Источник | Реализуется требованиями | Проверяется |
| :--- | :--- | :--- | :--- |
| БП-3 — указывать источник и автора видео | Юридический отдел | `.ПросмотретьВидеоролик` (отображение атрибуции в плеере) | Визуальная проверка плеера |
| БП-4 — статистика обновляется после завершения quiz | Команда разработки | `.ЗавершитьQuiz`, `.СохранитьСтатистику` | Прерывание quiz до завершения — статистика не изменилась |
| БП-5 — запрет постоянного хранения и офлайн-просмотра | Юридический отдел | `.Кэширование` | Отключение сети после просмотра — ролик недоступен |
| БП-6 — уведомлять об отсутствии субтитров | Команда разработки | `.Субтитры`, ДК-2 | Ролик без субтитров — уведомление появилось за ≤ 1 с |
| БП-7 — не более 3 попыток загрузки | Команда разработки | `.Ошибка`, Над-1 | Имитация недоступности — переключение на текстовую карточку после 3-й попытки |

## 4. Внешние зависимости

| Зависимость | Что от неё зависит | Как система ведёт себя при отказе |
| :--- | :--- | :--- |
| Зав-3 — библиотека видеофайлов | ВИ-11 целиком, ДК-1, Над-2 | Деградация до текстовой карточки со словом и озвучкой (ВИ-11 3а1) |
| Зав-3 — субтитры в библиотеке | `.Субтитры`, ДК-2, БП-6 | Уведомление + предложение транскрипции или переход к озвучке (ВИ-11 3а3) |
| ПрИ-2.1 — контракт с библиотекой | Все требования группы `Видео.Контекст` | Функциональность недоступна, требуется согласование контракта |

## Как читать матрицу

**Аналитику** — проверить полноту: каждый шаг сценария и каждое расширение должны иметь хотя бы одно требование в строке. Пустая ячейка в колонке «Функциональное требование» означает пропущенное требование.

**Разработчику** — понять, почему требование сформулировано именно так. Колонка «Бизнес-правило» показывает, что можно менять на техническом ревью, а что пришло из юридического отдела и обсуждению не подлежит.

**Тестировщику** — построить тест-план. Раздел 3 задаёт проверку каждого бизнес-правила, раздел 4 — сценарии отказа внешних зависимостей.
