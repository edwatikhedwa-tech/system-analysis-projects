# Постановка задачи разработчику — стриминговый сервис Otium

Доработка SOAP-метода: новый фильтр в контракте API, исправление невалидных XML-схем запроса и ответа.

> Учебный кейс курса «Системный аналитик». Текст задания не публикуется — здесь только моя постановка.

---

## Задача

Стриминговый сервис Otium продвигает эксклюзивный контент как ключевое преимущество подписки. Пользователю нужна возможность отфильтровать библиотеку так, чтобы видеть только эксклюзивы платформы.

Технически это означает доработку метода `{{WebServer}}/content/list`, который агрегирует данные от `FilmsServer` и `SeriesServer`. Признак эксклюзивности в источниках уже есть — не хватает параметра фильтрации в запросе и проброса признака в ответ.

**Моя роль:** системный аналитик — постановка задачи разработчику и правка контракта интеграции.

## Что сделано

- Сформулировал цель, требование и Use Case, включая поведение при снятом фильтре и совместную работу с другими фильтрами
- Описал изменения контракта: новый элемент `exclusiveOnly` в запросе, `exclusive` в каждом объекте ответа, логика обработки параметра
- Зафиксировал контекст: признак эксклюзивности уже приходит от источников, новых интеграций не требуется
- Провёл ревизию XML-схем `GetContentListRequest.xsd` и `GetContentListResponse.xsd`, нашёл **11 ошибок**, из-за которых схемы были невалидны
- Внёс исправления и добавил элементы, необходимые для реализации задачи
- Довёл тикет до версии 1.2 по итогам обсуждения с командой

**Результат:** постановка, по которой разработчик правит контракт, не задавая уточняющих вопросов, и валидные XSD-схемы.

## Найденные ошибки в схемах

| Категория | Примеры |
| :--- | :--- |
| Структурные | `sequence` без обёртки `complexType`; отсутствующие закрывающие теги в блоках `team` и `cast` |
| Типизация | `contentId`, `genreValue`, `ageRate` без атрибута `type` |
| Кардинальность | `content` без `maxOccurs="unbounded"` — список мог содержать только один элемент |
| Синтаксис | Лишняя `]`; типографская кавычка вместо прямой; слэш перед атрибутом `type`; пустые атрибуты `name` |

Ошибка с `maxOccurs` — самая коварная: схема выглядит рабочей и проходит проверку на одном элементе, а список из двух фильмов уже не валидируется.

Полный разбор с исходными и исправленными схемами: **[ticket.md](ticket.md)**.

## Выводы

- **Правка контракта интеграции — рискованная операция.** Поэтому в тикете разделены две вещи: «починил, чтобы схема стала валидной» и «изменил, потому что этого требует задача». По существу добавлено одно поле — остальное восстановление работоспособности схемы.
- **Значение по умолчанию не дублируется в схеме.** Поведение при отсутствующем `exclusiveOnly` описано в тикете и реализуется в обработке. `default` в XSD стал бы вторым источником правды, который разойдётся с логикой при первом изменении требований.
- **Раздел «Контекст» экономит день работы.** Указание, что признак `exclusive` уже приходит от `FilmsServer` и `SeriesServer`, снимает вопрос «а откуда брать данные» до того, как разработчик начнёт его выяснять.
- **Версионность тикета — история решений, а не бюрократия.** По переходу v1.0 → v1.2 видно, какие вопросы задала команда и что из-за них изменилось в постановке.
