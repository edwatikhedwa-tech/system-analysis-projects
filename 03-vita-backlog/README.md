# Бэклог приложения для сети клиник «Вита»

Командный проект: карта пользовательских историй, потоки данных и прототипы приложения для пациентов сети медицинских клиник.

> Учебный кейс курса «Системный аналитик». Текст задания не публикуется. Проект выполнялся командой из четырёх аналитиков — мои истории на общей карте отмечены отдельным цветом.

---

## Задача

Сеть медицинских клиник «Вита» запускала мобильное приложение для пациентов. Требовалось перевести бизнес-цели в структурированный бэклог: что именно разрабатывать, в каком порядке и по каким критериям считать сделанным.

**Моя роль:** системный аналитик в команде «Лето». Моделирование потоков данных и разработка части пользовательских историй с критериями приёмки.

## Что сделано

- Смоделировал потоки данных приложения (DFD): взаимодействие пациента, приложения, медицинской информационной системы и врача
- Разработал свою часть карты пользовательских историй с критериями приёмки
- Согласовал истории с прототипом интерфейса — связь «история → экран»
- Синхронизировал границы своей части с остальной командой: пересечения в бэклоге разбирались на общей доске, чтобы одна и та же функциональность не оказалась описана дважды по-разному

## Выводы

- **DFD полезно рисовать до бэклога.** Каждый поток данных превращается в конкретную историю, и ничего не теряется при декомпозиции.
- **В медицинской предметной области роли и права доступа критичны.** Что видит пациент, что видит врач, что уходит в медицинскую информационную систему — это отдельные истории, а не «подразумеваемое» поведение.
- **Критерии приёмки пишутся вместе с историей.** Сформулировать их постфактум означает додумать за заказчика то, о чём он не говорил.
- **Командная работа над одной картой требует явных границ.** Цветовая разметка по авторам решает не вопрос учёта, а вопрос ответственности: видно, к кому идти с вопросом по конкретной истории.
